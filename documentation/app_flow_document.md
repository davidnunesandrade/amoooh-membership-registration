# App Flow Document for AMOOH Membership Registration

## Onboarding and Sign-In/Sign-Up
When a new user arrives, they first land on the application’s welcome page. This page briefly explains the benefits of joining and offers clear options to sign up or sign in. A prospective member clicks the Sign Up button, which opens the registration form. They enter their name, email, and password, then submit to create their account. Upon submission, the server sends a confirmation email and activates their membership once they verify their address. If the user already has an account, they click Sign In and provide their email and password to authenticate. Users who forget their password click the “Forgot Password” link, enter their email address, and receive a reset link by email. The link leads them to a secure page where they enter and confirm a new password. Once they reset the password, they can sign in again. After signing in, the session is stored in a secure cookie until the user chooses to sign out by clicking the Log Out button in the header, which ends the session and returns them to the welcome page.

## Main Dashboard or Home Page
After a successful login, the application directs the member to their Dashboard. Across the top, a header displays the AMOOH logo, the user’s name, and a profile menu. Along the left edge, a vertical navigation bar lists links to key areas: Profile, Media, Agencies, Advertisers, Reporting, and Settings. In the center of the Dashboard, a welcome widget greets the user by name and highlights recent activity or announcements. Below it, quick-action cards allow the user to jump directly to adding new media, viewing agency lists, or generating a report. The sidebar remains visible on every internal page, letting the user switch between modules at any time. The header always shows a log-out button and a notifications icon that alerts the user to new messages or status updates.

## Detailed Feature Flows and Page Transitions

### Member Profile Editing
When the user clicks Profile in the sidebar, the application loads the Member Profile page. The page displays fields for contact details, company information, and their current role. The member clicks Edit, changes the information, and then clicks Save. The form sends a PUT request to the /api/members/[id] endpoint. The server verifies the user’s session, confirms the user owns this profile, and updates the database. The page refreshes to show the updated details.

### Display Medium Management
Clicking Media in the sidebar takes the user to the Media List page. Here, they see a table of all display mediums they have access to, showing name, type, and status. To add a new medium, the user clicks the Add New button at the top. A Media Form appears with fields for the medium’s name, category, and URL. Submitting the form sends a POST request to /api/media, and on success, the new medium appears in the list. To edit an existing entry, the user clicks the medium’s row, which navigates to /dashboard/media/[id]/edit. There they update fields, click Save, and the page issues a PUT request to /api/media/[id]. A Delete button also triggers a confirmation modal, and if confirmed, sends a DELETE request to /api/media/[id], removing the entry.

### Agency and Advertiser Workflows
Selecting Agencies loads the Agency Management page. A list of agencies appears, each with an Edit link. The user can create a new agency by clicking Create Agency, filling out the agency form, and submitting to /api/agencies. Inside an agency’s detail view, the user sees a list of associated advertisers. They click Add Advertiser, fill in the advertiser form, and submit to /api/advertisers, linking it to the current agency. Editing or removing an advertiser follows the same pattern of navigating to the advertiser’s edit page and issuing a PUT or DELETE request.

### Reporting Interface
When the user clicks Reporting in the sidebar, the Reporting Dashboard loads. This page features a data grid of past performance metrics and an interactive chart. The user can filter by date range or category. Every filter change triggers a request to /api/reports with query parameters. The server returns filtered, paginated data, which updates the table and the chart in real time. The user can export the results as a CSV by clicking the Export button, which downloads the current dataset.

## Settings and Account Management
From the sidebar, clicking Settings opens the Account Settings page. The user can update notification preferences, such as email alerts or in-app messages. They toggle switches and click Save to store changes. Under Billing, the user sees their subscription plan and payment method. They can click Change Plan to view available tiers and select a new one, which sends a request to the billing API endpoint. They can also update credit card details by clicking Edit Payment Method, filling out the secure form, and saving. Upon any change, the system confirms success and returns the user to the main Settings view.

## Error States and Alternate Paths
If the user enters an incorrect email or password at login, the Sign In form displays an inline error message asking them to check their credentials. If a network connection drops during a form submission, a notification appears at the top of the page stating that the request failed and to try again. During profile updates or media edits, if the server rejects invalid input, the form highlights the offending fields and shows descriptive error text. If a user attempts to access a resource they do not own, such as editing another member’s profile, the API returns a 403 Forbidden error. The application captures this and displays a message saying the action is not permitted, then redirects the user back to their Dashboard.

## Conclusion and Overall App Journey
A typical user journey begins with arriving at the welcome page, signing up with their email and password, and verifying their account. After signing in, the member explores the Dashboard and navigates to various modules using the sidebar. They begin by updating their personal and company details in the Profile section. Next, they manage their display mediums through the Media pages, creating and editing entries. They then oversee agencies and add advertisers under each agency. Regularly, the user visits the Reporting section to check performance data and export reports. Finally, they adjust notification settings and manage their subscription under Settings. Throughout their usage, the application guides the user clearly from one page to the next, handling errors gracefully and ensuring that every action leads smoothly back to the main Dashboard.
